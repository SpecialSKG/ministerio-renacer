# Checklist de implementación

## Antes

- [ ] Tipo de producto, superficie y nivel identificados.
- [ ] Stack, convenciones, componentes, tokens y utilidades inspeccionados.
- [ ] Compatibilidad, comportamiento y alcance autorizado entendidos.
- [ ] Referencias mínimas seleccionadas; SEO solo si pasa su puerta.
- [ ] Comandos reales de validación localizados.

## Durante

- [ ] Cambio mínimo enfocado en la causa.
- [ ] Comportamiento existente preservado salvo autorización explícita.
- [ ] HTML nativo, design system y primitives existentes preferidos.
- [ ] Estados relevantes: loading, empty, error, disabled y retry.
- [ ] Datos externos validados y errores visibles/accionables.
- [ ] Sin contenido, rutas, métricas o requisitos inventados.
- [ ] Sin dependencia, tracking o cambio arquitectónico implícito.
- [ ] Para email, aplicado el contrato específico en lugar de modernización web.

## Antes de cerrar

- [ ] Build, lint, typecheck y tests existentes ejecutados según alcance.
- [ ] Flujo afectado revisado en runtime cuando sea posible.
- [ ] Consola/network y responsive comprobados cuando aplican.
- [ ] Teclado, foco, nombres accesibles y reduced motion revisados.
- [ ] Diff inspeccionado por cambios incidentales.
- [ ] Verificaciones no ejecutadas y riesgos declarados.
